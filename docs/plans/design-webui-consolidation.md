## 1. 现状诊断（实测数据）

| 维度 | 现状 | 判断 |
|---|---|---|
| 视图代码 | `views/` 8145 行 / 13 个视图，最大 `sessions.tsx` 1925 行 | 单文件过大 |
| 组件 | `components/` 3802 行 / 18 个 | 缺表单与浮层类原语 |
| 样式 | 8185 行 / 7 个文件，其中 `views.css` 5317 行（65%） | **分层已退化** |
| 跨文件重复选择器 | **35 个**（`.input` `.btn` `.badge` `.card` `.field-*` `.modal*` `.spinner` `.hint` …） | 层叠靠加载顺序 |
| 响应式 | 8185 行 CSS 仅 **7 个** `@media`，断点值 860/900/960/720/420 五种 | 移动端近乎无覆盖 |
| 无障碍 | `aria-*` 106 处、`role` 56 处，但 `tabIndex` 仅 **7**、`onKeyDown` 21 | 有基础、不成体系 |
| 设计 token | `tokens.css` 405 行，暗色集中一处，`tokens.css` 外的硬编码颜色仅 8 处 | **底子是好的** |
| 内联样式 | TSX 中 35 处 `style={{…}}` | 绕过设计系统 |
| 时间格式 | 18 处散落的 `new Date()/toLocale*`，`format/` 下只有 `json` | 一致性缺口（P2 项） |
| 产物体积 | JS 527 KB（gzip 162 KB）/ CSS 133 KB（gzip 22 KB），构建已警告 >500 KB | 需代码分割 |

**结论：token 层是健康的，问题出在「分层与组件化」。** `styles.css` 的注释写着各层按 `@import` 顺序叠加、"last wins on equal specificity"——`views.css` 作为历史遗留的 "carried view rules" 层，已经与 `components.css` 大面积重叠，改一处容易踩另一处。

> 例证：本次修「添加模型」下拉时踩到的 `.field-row` 按钮换行，根因就是 `.input{width:100%}`（components.css）与 `.u-flex-1{flex:1 1 auto}`（views.css）跨层叠加。

## 2. 设计原则

1. **Token 是唯一真相** —— 颜色/间距/圆角/阴影/字阶只从 `tokens.css` 取，不新增硬编码。
2. **一层一责** —— token → primitive（`.btn`/`.input`/`.card`/`.badge`）→ pattern（字段组/对话框/工具栏）→ view。同一个选择器只在一个文件里定义。
3. **状态三件套** —— 每个数据视图必须显式处理「空 / 载入 / 错误」。P1 已有 `PageHeader`/`ErrorState`/`LoadingState`，继续强制走它们。
4. **键盘与触屏是一等公民** —— 可点即键盘可达；可拖即键盘可移。
5. **增量、可回滚** —— 每阶段一个独立 PR，每步都要 `npm run typecheck && npm test && npm run build` 通过。

## 3. 目标架构

```
① Token        tokens.css          颜色 · 间距 · 圆角 · 阴影 · 断点
② Primitive    components.css      .btn .input .card .badge .field-*
③ Pattern      components/*.tsx    Modal · Popover · Form · PageHeader
④ View         views/*.tsx + views.css   只保留视图私有类
```

依赖方向自上而下；`views.css` 不再定义任何 primitive。

## 4. 落地方式：一个选项卡 = 一个页面 = 一个 PR

不做横切式的大重构，而是**按侧栏选项卡逐页推进**，每页一个独立 PR、独立验收。好处是每个 PR 的 diff 只碰一个视图 + 它自己的类，review 面小、回归面小、可以随时停在任意一页。

### 4.2 每个页面 PR 的固定清单

1. **布局与信息层级** —— 该页自己的问题（含空态该给什么主行动、主次按钮是否分明）
2. **三态齐全** —— 空 / 载入 / 错误都走 `PageHeader` / `ErrorState` / `LoadingState`
3. **可及性** —— 可点即键盘可达；`aria` 标签、焦点顺序、`Esc` 行为
4. **响应式** —— 该页在 3 档断点（640 / 960 / 1280）下的行为
5. **一致性** —— 时间格式、badge、按钮层级、文案走 i18n（五语言同步）
6. **范围纪律** —— 只动该页的 `tsx` 与它自己的类；发现共享层问题只记录、不当场改

### 4.3 共享层：单独出 PR，不混进页面 PR

页面之间会反复撞到同一批重叠样式（35 个跨文件重复选择器）。约定：

- 共享层改动单独出 PR，分支名 `refactor/webui-shared-*`，候选清单：
  - 断点收敛为 3 档 token（`--bp-sm` 640 / `--bp-md` 960 / `--bp-lg` 1280），替换现有 5 种
  - 35 个重复选择器归位：primitive 只留 `components.css`，`views.css` 只留视图私有类（先「移动不改值」，视觉零变化）
  - 抽 `components/form.tsx`（`FieldGroup`/`Input`/`Select`/`Hint`）与 `components/overlay.tsx`（`Modal`/`Popover`/`Menu`，推广 `model-picker.tsx` 刚建立的浮层模式）
  - 新增 `format/time.ts` 统一时间口径
  - 加「重复选择器」lint 腿（与 `scripts/check-docs.sh` 同族），防止再次退化
- 页面 PR 遇到共享层问题 → 记进下面的清单，不在页面 PR 里顺手改
- 某个共享改动若阻塞了某页，就在那页 PR **之前**单独提掉它

## 6. 不做什么 / 风险

- **不换框架、不引入 CSS-in-JS 或 UI 库**：Preact + 全局 CSS 是刻意的轻量选择（要内嵌进单二进制），本方案只做收敛不做替换。
- **不做视觉大改版**：token 与配色保持不动，避免与上游 v0.0.11 的视觉语言分叉。
- **风险**：W1 触碰全局样式，必须逐页截图比对；所以采用「先移动、不改值」的策略把回归面压到最小。
- 流程：每个 PR 独立分支、独立验收。上游 #52 未合并前，新分支一律从 `origin/main` 拉，不从 fork main 拉。
